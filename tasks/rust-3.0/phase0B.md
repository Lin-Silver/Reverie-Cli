## 已确认的质量合同

每个 required 证据绑定固定提交、文件、包含两端的 1-based 行号、Git blob、完整文件 SHA-256、原始 UTF-8 片段及片段 SHA-256。计分使用产品实际返回的证据片段；路径、摘要、符号元数据或没有返回的正文不构成命中。

| 项目 | 固定规则 |
|---|---|
| 返回上限 | 评价时每个原生片段只计前 72 行，保留完整原始返回；Rust 产品实际片段仍须最多 72 行。总预算 12,000 估算 tokens，固定字符数 ÷ 4 算法 |

| 单题 Recall@10 | 命中的 required 证据数 / 该题 required 证据数 |

| 数学上限 | 先测正式 Python 基线；超过 90% 时报告上限，等待维护者决定目标形式，不能自行降低门槛 |
| 标签冻结 | 独立标注、交叉复核、原始字节及重复检查通过后冻结；观察成绩后禁止调整标签和证据范围 |

维护者已确认保留 Python 历史预算算法：任务正文估算为 `floor(len(context_string) / 4)`，`len` 按 Unicode 字符计数，Rust 使用等价的字符计数。12,000 是这套算法的估算 tokens，不称作真实 tokenizer 的精确计数；单独记录正文字符数和估算值，不能让两版用不同算法取得更多正文。超长返回、缺失来源或版本不明作为合同问题单独记录，不能靠评价器补出产品未返回的内容。

## 性能与轻量测量

参考机为已核实的 Windows Ryzen 5 5600X、6 核 12 线程、约 24 GiB 内存。每个版本和场景的冷启动、预热各至少 30 次，保存单次原始样本，计算中位数和 p95，不仅保存平均值。

1. 固定最终发行程序及 SHA-256、同机系统状态、语料文件集合、输出位置和内容、结果数、12,000 tokens 预算、线程、并发及缓存策略。Python 保留历史忽略，Rust 采用 Git 标准语义；性能夹具避免这项有意差异改变纳入文件集合。
2. 启动以界面及必要内核连接可用为终点；完整结构索引以结构、检索持久化及约定快照完成为终点；基础检索从请求到排序、片段选择与上下文组装完成。不能延后必要工作来退出计时。
3. 无插桩发行包 wall time 用于最终门槛。另用同源隔离进程分解启动、扫描、解析、图更新、序列化、IPC、数据库/快照、排序及上下文组装；追踪开销、并行重叠和关键路径独立报告，不相加线程时间冒充端到端时间。
4. 区分进程冷启动、索引缺失、文件系统缓存、查询结果缓存与模型预热。尚未控制或测得的缓存状态明确记录，不能将新进程自动称作文件系统冷缓存。
5. 桌面空闲内存使用相同工作区、历史、功能和稳定采样窗口，统计 Electron 与相关进程工作集和私有提交量。安装包采用同格式，报告压缩/解包/组件/总量，语义资源单列；无索引冷启动另报中位数及 p95。三项均不得退于最终 Python。
6. 基础语义链以 GPU 关闭、单查询并发、重排 `N=16` 测 CPU p95≤2 秒；缓存命中和实际推理分别报告，完整链包含向量化、召回、融合、重排和组装。
