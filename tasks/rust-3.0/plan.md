### 完整恢复版，纳入纯 Python 2.5.5 重发与工程收整前置

此前完整的 3.0 计划仍保存在本会话的计划卡片中，没有从仓库删除。上一版将 Rust 主计划压缩成了承接清单，遗漏了实施内容，不能作为完整替换版使用。

本版恢复原计划的架构、功能迁移、Context Engine、市场与授权、GUI/TUI、Gamer、Live2D、性能验收和发布安排，并保留你之后确认的调整。项目收整和纯 Python 2.5.5 重发作为前置阶段，Rust 3.0 仍是本会话的主要目标。

**当前状态：最终纯 Python 2.5.5 已重发并冻结完整归档。根据维护者 2026-11-23 的最新决定，仅保留 `main` 和 `Reverie-Cli-py` 两个分支，直接在 `main` 推进 Rust 3.0 重写。本地执行基本构建、针对性行为测试和运行检查；其余验收列入 [未验证清单](UNVERIFIED.md)，由 [云端 Agent 提示词](CLOUD_VALIDATION_PROMPT.md) 承接，不再作为开始 Rust 实施的阻塞。既有结果、原失败和完整产品范围保留，未验证项不改称通过。**

## 一、目标、当前状态与实施前置

### 1.1 Rust 3.0 的完整交付目标

在 `G:\Reverie\Reverie-Cli\ReverieCli-rs` 建立 Rust 工作区，重写 Python 承担的第一方内核、上下文引擎和终端程序，保留 Electron/React 桌面并连接同一 Rust 内核。

3.0.0 的范围包括：

- 现有全部第一方功能、命令、模式、工具、会话、记忆及任务行为的迁移。
- 更强的本地 Context Engine，包含结构索引、基础检索、向量召回、混合融合及神经重排。
- 滚动式终端，以及完整的桌面与终端管理流程。
- 四个内置市场、手动来源、通用扩展组件和公开 MCP Connector 授权。
- 普通完整 2D、2.5D 游戏和 3D 小游戏的 Gamer 制作闭环。
- 独立官方 Live2D 插件，使用原生 Cubism 渲染。
- 四平台真实构建、原生包验证、旧数据接续和正式 GitHub 交付。

### 2.4 Context Engine 的完整实施结构

**结构索引：**

- 增量扫描、忽略规则、文件变化和工作区身份。Rust 默认采用已确认的 Git 标准忽略语义：父目录被排除时，必须先重新纳入父目录才能重新纳入其中的文件。用独立兼容夹具核对这项有意差异；性能对照语料固定同一纳入文件集合，不能借排除更多文件达到门槛。
- Tree-sitter 解析、符号、引用、依赖及位置。
- Git 变更与历史。
- 配置、文档、小说和游戏资源。
- 正式基线支持的语言和文件类型。
- 解析失败、超大文件、重命名、删除、缓存修订及重启恢复。

**基础检索：**

- 精确标识符、符号、路径、锚点和词法检索。
- 排序、过滤、去重和证据定位。
- 依赖扩展、历史、长期记忆及指令发现。
- 上下文预算、压缩、片段选择和缓存失效。
- 查询到上下文组装的完整链路。

**语义增强：**

- 真实向量索引和近邻召回。
- 词法、结构与向量结果的混合融合。
- 有限候选神经重排。
- 中英跨语言、无精确标识符和跨文件难例。
- 统一返回路径、位置、内容版本和来源证据。

**一致性与生命周期：**

- 项目共用索引和修订管理，保护竞争写入。
- 基础索引及时更新，语义索引按修订追赶。

| 校验项 | 内容 |
|---|---|
| 来源身份 | 对应已安装来源及插件，固定提交/发行修订；发布者、来源或信任密钥变化需确认 |

| 安装路径 | 绝对路径、穿越、越界链接/reparse point、重名覆盖及入口范围 |
| 依赖与许可 | 版本、取得方式、安装动作及许可材料；新增依赖和脚本先确认 |
| 运行健康 | 受控解析、启动、握手、必需注册和配置加载；不执行业务 Hooks/命令或发起新授权 |

现有目录变化检测“signature”不能作为发布者数字签名。

缺少发布哈希、可验证签名且无法按固定 Git 内容验证的更新，保留候选，不自动启用或运行入口。用户批准具体候选哈希后，才继续验证。

哈希错误、无效签名、身份不符、损坏、越界或明确不兼容直接拒绝。对缺依据候选的批准不能绕过这些失败。

**原子切换：**

1. 下载、解包和校验在独立版本目录完成。
2. 切换前复核当前版本、信任、启用状态及批准范围。
3. 原子提交单一激活记录，绑定版本、内容身份和受管注册。
4. 已运行任务固定旧版本；独占组件等待旧任务结束，不强制终止。
5. 新版必需健康失败时恢复上一可用激活及注册。
6. 保留上一可用版和仍被任务引用的版本。
7. 重启恢复一致状态，避免混合新旧文件。

原子保证针对安装及激活状态。业务数据迁移另走一致性备份；不能证明回退兼容时暂停自动更新并确认恢复方案。

验收覆盖篡改、截断、缺依据、无效签名、来源替换、错误平台/协议、危险路径、新权限/依赖、健康失败、并发、中断、重启和 Windows 文件占用。

第一方语言服务驱动采用 Rust，按项目和内容版本管理外部服务器、诊断、定义、引用、超时和退出。Rust 编写的成熟服务器优先使用；其他语言的既有服务器按实际运行时及许可管理，不能将服务器自身运行时误报为 Rust 内核的 Python 依赖。内置服务器的启用及来源策略仍须完成明确接入；市场和手动服务器继续遵守显式信任流程。

完整 VS Code 扩展宿主会增加 API、激活事件、文档模型和扩展进程兼容范围，当前工程评估不足以支持该成本。保留现有工作台；Monaco、Open VSX 和具体扩展不因本次评估自动成为依赖或第五个内置市场。Void 的固定源码主要为 TypeScript 的 VS Code 分支，其许可与市场访问限制按 [评估记录](browser-ide-assessment.md) 分开核对。

### 4.2 正式性能基线与可达性

主基线使用重发并验收的纯 Python 2.5.5。原混合版保留对照，不能混用两版数据。

每个版本、场景的冷启动和预热各至少 30 次，分别计算中位数和 p95。

本机硬门槛采用已确认 Windows 参考机：Ryzen 5 5600X、6 核 12 线程、约 24 GiB 内存。固定系统、线程、并发、语料、缓存和输出契约。

- 区分进程冷启动、索引缓存缺失和文件系统缓存状态。
- 固定语言、文件、符号、过滤、结果数、位置、上下文预算和持久化。
- 启动计时到界面及必要内核连接可用。
- 结构索引计时到约定索引及持久化完成。
- 基础检索计时到结果及上下文组装完成。
- 必要工作不能通过延后执行退出计时。

分解启动、扫描、解析、序列化、IPC 等待与传输、排序、上下文组装、数据库及快照成本。正式包未插桩 wall time 判定门槛，追踪只作归因，记录开销、重叠和关键路径。

| 阶段 | 当前可达性判断 |
|---|---|
| 启动 | Python 引导及重复初始化有改善空间；Electron 和原生库固定成本须测量 |
| 扫描 | Rust 编排可能改善 Python 路径，文件系统成本仍形成下界 |
| 解析与图更新 | 数据组织、复制和图操作有空间，原生解析本身不能假定减半 |
| 序列化与 IPC | 最终纯 Python 的内核与索引已同进程，索引 IPC 为零；Electron JSONL 桥接保留，不能将历史 Rust worker 的 IPC 当作新基线优化空间 |
| 排序与融合 | SQLite 和原生检索成本需实测，不能仅凭语言转换承诺 |
| 上下文组装 | 预算、依赖扩展、去重和复制可能改善，尚未验证 |

这些是推断。最终纯 Python 发行来源已经固定，阶段 0B 的耗时样本尚未完成；当前没有足够证据确定各阶段占比及减半可达性。

阶段 0 给出原始样本和 Amdahl 下界。保留成本超过整体 50% 时，仅优化其他部分无法使整体减半。

**启动、完整结构索引、基础检索的中位数与 p95 均须≤主基线的 50%。** 诊断小段不另设减半门槛。整体不可达时保持未通过，提出明确定义的替代口径由你决定。

### 4.3 质量、语义延迟与轻量门槛

- 基础检索质量不下降。
- 冻结难例 Recall@10 至少增加 10 个百分点。
- Recall@10 按已确认的证据片段口径评价：身份绑定固定语料版本、文件、位置及内容摘要。评价时每个原生片段仅计前 72 行，保留完整原文供审计；Rust 产品实际片段仍须最多 72 行。总预算 12,000 tokens，按返回顺序以完整原生片段去除完全重复项后取前 10，不拆成更多片段；完整覆盖预标注证据且版本一致才算命中。每题运行 30 次，每次以命中的 required 证据数除以该题 required 证据数，先取单题 Recall 均值，再逐题等权宏平均，各领域及范围、波动另报；supplementary 不进入 Recall 分母。独立标注和交叉复核通过后冻结，不以扩大片段、重复计数、改变预算或事后调整切块改善成绩。开发草案不等同于正式题集，准备与核验见 [阶段 0B](phase0B.md)。
- nDCG@10 只观测，不恢复早期推导的“相对提高 15%”门槛。维护者已确认 required=2、supplementary=1，完整覆盖且内容版本一致才获得等级，DCG 增益为 `2^等级−1`。按返回排名进行一对一匹配，每段最多计一项证据，每项证据只计一次，优先 required；同等级采用增广匹配消除歧义，理想序列取全部冻结证据的等级降序前 10。基础/难例观测宏平均为约 0.209155 / 0.035001，[逐次观测与原始返回摘要](python-ndcg-baseline-v1.json) 单独保存，冻结题集及 Recall 合同不变。
- 固定 Python 源码 API 的 48 题×30 次质量基线已完成并独立审计：基础宏平均 21.8750%，难例 5.2604%；据锁定门槛，Rust 分别须不下降和至少达到 15.2604%。实际判定使用 [完整精度及逐次样本](python-quality-baseline-v1.json)。这项结果不代替发行包性能，也不证明 Rust 已实现或通过。
- 12,000 tokens 使用维护者确认的 Python 历史任务预算算法 `floor(len(context_string) / 4)`，按 Unicode 字符数计，明确是估算值；两版采用相同算法并报告正文字符数，不能宣称真实 tokenizer 精确计数。
- 先测 Recall 基线；超过 90% 时报告数学上限，由你决定目标形式。
- GPU 关闭、单查询并发、`N=16` 重排候选，预热完整语义链 CPU p95≤2 秒。
- 固定输入长度、线程和缓存策略；模型预热、缓存命中和实际推理分别报告。
- Windows 本机承担性能硬门槛，其他三平台做原生、功能、兼容验收并报告性能。

轻量三项不得退于最终纯 Python 2.5.5：

| 指标 | 口径 |
|---|---|
| 桌面空闲内存 | 同工作区、历史、配置和功能，统计 Electron 与相关进程工作集及私有提交量，使用固定稳定窗口 |
| 安装包体积 | 同格式和功能集合，报告压缩、解包、组件及总量；语义资源单列 |
| 无索引冷启动 | 同机、同数据和就绪契约，对比中位数及 p95 |

基础内存使用语义模型未加载、Gamer 未运行的状态；语义预热和游戏成本另行完整报告。

历史桌面记录曾显示进程树工作集峰值 958.01→522.17 MiB、私有提交峰值 770.81→429.84 MiB。它属于旧版启动后采样，只用于恢复测量口径，不能作为当前空闲基线。

### 4.4 真实 DPI 与系统窗口

真实单屏 DPI 是核心候选包必需验证。

在同一物理显示器切换 100%、125%、150%、200% 系统缩放，每档验证：

- 桌面及窗口截图，原图、裁剪图和缩小返回图坐标。
- 普通、最大化、吸附分屏窗口边界及截图原点。
- 实际点击、拖拽，以控件状态或结果回读验证命中。
- 启动时 DPI 和运行中切换后的更新。
- 缩放、位置或尺寸变化后旧截图失效及重新观察。
- 完成或中断后恢复原缩放和环境。

延续 `image_id` 与 `returned_image_pixels` 契约，区分 DIP、屏幕物理像素和返回图像像素，依据捕获、裁剪和缩放元数据转换。

Windows 的窗口命中与遮挡检测也必须使用屏幕物理像素。调用 Win32 查询时核对线程 DPI 上下文，临时切换后恢复原值；坐标口径或恢复无法证明时拒绝输入，不能关闭遮挡检查。125% 实测已确认 DPI 未感知线程可能把有效物理端点识别为其他窗口，原代码及新候选结果分别留证。

窗口截图也必须绑定显示身份、物理边界及缩放快照，在捕获结束与输入前复核。真实运行中切换缩放的验收包含窗口物理边界保持不变的场景；不能只依靠窗口尺寸变化或图像自然过期证明旧图已失效。无法取得显示几何和缩放时拒绝坐标输入。

记录实际缩放、边界、图像尺寸、转换参数、投递位置和效果。模拟公式或字体变化不能代替实际命中。

真实验证 Windows Snap/Snap Layouts、虚拟桌面、窗口移动恢复、弹窗、焦点和后台任务的自然兼容。物理多屏保留设计与模拟覆盖，真实多屏作为额外观测。
