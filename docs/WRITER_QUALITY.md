# Writer 质量检查与评测

Writer 的软件行为和作品的文学效果分别验收。磁盘状态、章节长度、哈希和字符串重合能进行确定性检查；人物可信度、情绪、语言自然度和阅读吸引力需要阅读具体正文，无法从一个机械总分推断。

## 原生章节长度与恢复

新小说默认章节目标为10,000个非空白字符，硬下限为5,000。显式短章目标与旧项目继续使用原设置及原有交付分摊规则。新默认的10,000字是创作目标，最终 `audit` 仍要求达到整个小说的交付总量；若较短章节使计划篇数不足，需要继续后续章节。

字符统计排除空白，另记录汉字数；这两项不是同一口径，也不代表实际 Token 数。篇幅应由真实发生的场景、判断、选择、反应和后果支撑，不能靠重复段落或反复总结凑字数。

提交仍检查长度、重复段落、前章连续64个非空白字符重合、固定表达过度使用和待写标记。长度不足的草稿保存于 `drafts/`，下一次只追加新的 `append_content`；其他阻塞问题要求明确修订正文。替换草稿和明确修订章节会保存历史版本及提交来源。提交前核对草稿归档与原文件逐字节一致，归档失败时不发布章节；确认归档后的待提交草稿清理不触发工作区删除恢复，其他文件仍受原有保护。修订当前章节不会把它自身的原文误判为跨章节复制。

中文待写标记按独立行、括号标记及“此处／下文／后文／正文待补或省略”等明确形式识别。“记录写得太省略”“列出待补材料”等普通叙述不会仅因包含这两个词而阻止提交；TODO、TBD、PLACEHOLDER 和英文待写标记仍会被拦截。这是确定性的文本检查，不能识别所有语义上的内容缺失。

## 控制卡与编辑证据

章节控制卡保留大纲、场景节拍、连续性约束、关系推进、开篇与结尾安排。可按故事需要补充五项可选内容：

| 字段 | 用途 |
| --- | --- |
| `narrative_function` | 本章在故事中的作用 |
| `character_goal` | 角色当前想完成的具体目标 |
| `causal_change` | 选择或发现产生的后果 |
| `emotional_change` | 有互动依据的情绪或关系变化 |
| `reader_expectation` | 实际事件建立或兑现的阅读期待 |

这些是计划和审稿的依据，不要求每章填满，也不能把清单写进正文。安静场景、日常故事和轻喜剧可以用适合题材的推进方式。

机械报告提供实际位置、引用、影响和修订建议。中文长短语重复不依赖空格分词；重复短语属于审阅线索，可能是有意回声，不自动增加硬门禁。对白长度、疑问与感叹次数、词汇多样性属于描述性指标，不能证明人物声线一致。旧 API 的 `consistency_score` 和综合文学分数字段保留为 `null`，不再给出固定70%或伪装成文学判断的总分。

`/wstyle review` 是单独的模型编辑建议。引用必须真的出现在所指正文行，Card 引用必须来自当前有效组合；模型意见仍可能错误或遗漏重要背景。审稿还接收当前章节之前最近三章的摘要、事件、人物、关系和时间线记录，合计最多8,000字符；较早或超限的记录整条省略并列入报告，不静默截断事实。前章记录来自已保存的摘要和更新，不能代替前章全文核对。报告明确记录纳入的前章、省略的上下文、原文哈希和局限。执行审稿不改写原稿，也不改变原生提交结果。用法、预算和报告目录见 [WStyle 指南](WSTYLE.md)。

## 可重复的原创对照

[评测脚本](../scripts/verification/evaluate_wstyles.py)使用[原创测试集](../scripts/verification/wstyle_corpus.json)，提供三个题材：

- 暴雨后旧供水站的成年双女主百合，检查独立目标、职业判断、对白和信任变化。
- 魔法邮局的女性群像轻喜剧，检查制度限制、动机、信息差和有后果的笑点。
- 注销车票 `0417` 与旧打印日志的都市悬疑，检查证据、推断边界和下一步调查期待。

每个设定比较关闭 WStyle、单 Card、多 Card，使用同一模型和主要参数，按固定随机种子安排匿名样本标签。另有三章原生连续性练习，第三章切换组合，保存控制卡、提交记录和完整性审计。每篇至少5,000个非空白字符，目标10,000。只计算清理模型思考标记后的正文，排除章节与 Markdown 分节标题；标题不计入续写门槛，问题证据保持原文行号。原始响应另存用于追溯；达到 Token 上限的不完整输出不能冒充完成章节。

默认只生成离线计划，完全不调用模型：

```powershell
python scripts/verification/evaluate_wstyles.py --output .runtime/wstyle-evaluation-plan
```

明确允许使用已配置 Provider 后才执行真实生成，例如：

```powershell
python scripts/verification/evaluate_wstyles.py --output .runtime/wstyle-evaluation-live --execute --source sensenova --model sensenova-6.8-flash --allow-model-usage --max-tokens 65536 --reasoning-effort none
```

`--allow-model-usage` 包含可能产生费用的 Provider 调用；不传此标记时，执行只允许经实时目录确认输入、输出价格均为零的 OpenCode 模型。HTTP 限流和配额错误仍可能发生，不能把“免费”当作可用性保证。

长篇评测单次 Token 预算为8,192–65,536、超时上限300秒、无自动 API 重试；不要套用审稿与提取的编辑预算。`--reasoning-effort` 只覆盖本次 SenseNova 评测，不保存到应用设置，不能对由 Provider 管理思考的模型选择不存在的强度。模型和线路是否实际遵循请求选项，需要检查返回结果。

输出目录包含 `corpus.json`、`run.json`、`blind/` 正文、`private/` 提示词和 Card 对照、原始响应、表面观察及 `reader-review.md`。失败保留诊断。相同条件恢复可加 `--resume`；已修改的正文或不匹配的请求不会被覆盖。Reader 正文与原始响应分开保存，原始响应中可能含有模型的规划文本。

## 阅读方法与结论边界

先阅读匿名正文，记录语言、人物、因果、情绪、节奏、连续性、重复和阅读期待的具体位置、引用与影响，再解盲核对 Card 目标。记录不同意见和无法确定之处，避免“多卡更长，所以更好”的结论。模型审阅应明确标为模型意见，不能伪称独立读者评价。

字符串命中只能说明名字或物品被提到，不能证明故事事实被正确理解。三类设定的一次对照不能证明普遍提升；三章只能检验短程承接，不能证明十万字长篇稳定。没有真实读者、平台数据或授权文本研究时，不编造完读率、签约、推荐、收益或跨作者因果规律。
