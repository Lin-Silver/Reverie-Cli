# Python 2.5.5 release verification

The final Python 2.5.5 source uses an entirely Python Context Engine, shared in-process by CLI, SDK, and Electron Desktop. The original mixed 2.5.5 remains a separate historical source and release identity. A new tag or package version alone does not establish acceptance of the pure Python reissue.

## Pure Python reissue contract

- Bind every verification result to its source commit and actual program/package SHA-256. Reuse no mixed-version verdict as a Python-backend pass.
- Complete software regression and native Windows x64, Linux x64, macOS arm64 and x64 builds. Independently verify actual CLI/SDK/Context Engine programs, package/kernel manifests, platform, architecture, sizes and digests.
- Verify incremental indexing, ignore rules, rename/delete, failed-write rollback, revision/caches, process shutdown, and consistent historical-index backup with an actual restore/rebuild exercise. Preserve configuration, session text, manuscripts, and other original project data.
- Verify Computer Use on one physical display at actual 100%, 125%, 150%, and 200% Windows system scaling: original/cropped/resized image coordinates, real clicks and drags, normal/maximized/Snap windows, changes during runtime, stale-image rejection, and restoration of the original environment.
- Preserve the original tag object, source, assets and evidence before reissuing 2.5.5. Compare the final tag/source and independently downloaded asset manifests, runtime Python-backend records, sizes and SHA-256 values.
- Stable CI uploads all 17 assets to a draft. This session verifies the actual downloaded assets and physical DPI behavior of those programs before publishing the draft; upload success alone does not make it public.

Candidate progress is tracked independently from the original closeout. Final release notes and source-bound evidence report actual completed checks and unresolved limits; this contract does not assert that pending checks passed. The fresh eight-hour AiO run, physical multiple displays, complete clean-host/foreground product and real-model literary acceptance are explicitly waived as Rust-start prerequisites, and remain unverified unless separate evidence is obtained. All software, Python Context Engine, actual single-display scaling and reissue identity checks above remain required.

## Preserved failures and limits

- The first Desktop run timed out during a worker startup handshake. The affected 122-test module and an unchanged complete 527-test rerun passed. The startup long-tail root cause is not established.
- The final documentation candidate's Windows CI failed before a WStyle boundary assertion because its PowerShell junction-creation subprocess exceeded 20 seconds. The original test passed locally in 0.96 seconds; the CI startup cause is not established. The test fixture now uses the Windows native junction API and explicitly verifies the mount-point reparse tag before running the unchanged rejection and external-directory assertions. Product code and acceptance workloads are unchanged; final CI runs again for this test-only repair.
- The baseline Intel native input test failed at p95 160.5 ms with 60 samples against the original 100 ms gate. A same-package diagnostic at 94.8 ms did not replace the failure. The unchanged complete job rerun passed at 93.4 ms. The long-tail root cause is not established.
- One real SenseNova review returned malformed JSON. The product rejected it and preserved the manuscript and diagnostics. A complete repeat using the identical request SHA passed; successful repetition does not guarantee provider output reliability.
- An earlier private Writer verifier incorrectly required the whole novel-directory file set to remain identical after review. It counted the expected new review artifacts as manuscript changes. The corrected verifier still requires every pre-existing file to remain byte-identical and permits only the exact expected new evidence files. Original failed attempts remain retained.
- Native CI uses synthetic loopback model fixtures and has zero model-quality samples. Its software, package and performance verdicts do not rate real-model task quality.
- Independent reading of the generated chapter found a missing causal step for replacement-rope delivery, inconsistent lighting details, and repeated endings after append-only continuation. Literary quality was not accepted. The chapter did not reach its 10,000-character target; the novel was not completed.

The following earlier acceptance work was not completed for this release: a fresh single continuous 28,800-second package run; full real-provider AiO scheduling, switching, recovery and memory product flows; final-package Computer Use foreground/visual/physical-input and cancellation flows; real mixed-DPI physical multi-monitor testing; complete clean-host install/portable/old-data recovery/uninstall acceptance; all remaining real-provider RIU and Writer desktop flows; and the full multi-sample and complete-novel literary evaluation. Historical evidence from older source/package identities does not turn these into final-package passes.

Release publication and the archive baseline use the explicitly narrowed software/build/tool scope above. Existing feature contracts and failed evidence are preserved. Back up existing configuration, conversations and manuscripts before upgrading. Reverting to a previous published binary is available if a product regression is encountered; backups preserve data independently of that binary choice.
