# Reverie v2.5.5

- Final Python closeout reissue preserving the full Python project, Electron desktop, and existing functionality. The Context Engine now runs entirely in Python through the same CLI, SDK, and Desktop indexer; the former Rust index worker is no longer built or bundled. The independently verified reissue source becomes the complete-project baseline for `Reverie-Cli-py` and the later Rust 3.0 rewrite.
- Preserved standalone `--context-engine` indexing, search, symbols, paths, status, help, version, and JSONL service commands. Incremental updates retain transactional manifest/FTS writes and revision-specific snapshots. Historical Rust indexes are consistently backed up and retained while Python derived indexes are rebuilt.
- Restricted candidate and archive branches to CI artifacts: their pushes and manual workflow runs cannot publish core or plugin releases. Main/manual and version-tag publication retain source, version, integrity, and exact-source Test gates.
- Durable AiO and independent conversations with per-conversation model/rule configuration, background execution, task recovery, lifecycle controls, memory correction/deletion, and full-text exports.
- Fixed SQLite connection lifecycle and Windows project-data deletion, incremental Context Engine cache refreshes, Windows native database and Computer Use state paths, bounded workspace discovery, and duplicate token-accounting work.
- Fixed workspace-statistics startup contention when multiple processes initialize WAL, preserving the original concurrency and durability requirements.
- Closed unfinished provider responses with their owning client, preserving other clients' shared keepalive connections.
- Closed desktop SDK kernels through their shutdown protocol and waited for normal exit, with bounded forced cleanup for unresponsive processes.
- Omitted two quarantined upstream offline references, `rce.md` and `文件漏洞.md`, from bundled resources. Their unavailability is documented in upstream provenance; skill entry points and the remaining resources are preserved, and the original files remain in Git history.
- Allowed valid desktop Writer planning and chapter turns to remain resumable, while rejecting missing or corrupt native project state and preserving terminal whole-project completion requirements.
- Corrected Writer progress checks for prompts with punctuation after the novel ID across all supported systems.
- Recovered Writer text tool calls without mixing planning text or tool parameters into chapter prose; incomplete or unrecognized wrappers stay outside manuscripts and request a valid continuation.
- Fixed RIU selected-conversation ownership and native package-verification fixture isolation. Preserved Writer/WStyle, model/provider routing, SDK integration, native Computer Use, and their existing acceptance contracts.
- Refreshed version-dependent build metadata and required successful native package checks plus the exact source commit's Test workflow before publication. Required downloads cover Windows x64, Linux x64, macOS Apple Silicon, and macOS Intel, with matching kernel verification metadata.

The pure Python reissue requires full software regression, all four native release builds and actual package verification, CLI/SDK/Context Engine checks, and real single-display Computer Use validation at 100%, 125%, 150%, and 200% system scaling. Source, tag, asset identity, size, SHA-256, and Python backend records must agree before stable publication. See the [verification contract, historical evidence, and limits](https://github.com/Lin-Silver/Reverie-Cli/blob/v2.5.5/docs/releases/v2.5.5-verification.md).

The original mixed 2.5.5 source, assets, and evidence are retained separately. Its tests and controlled real-provider Writer checks are historical evidence and do not establish acceptance of the new Python implementation. A fresh continuous eight-hour AiO run, real physical multiple-display testing, complete clean-host/foreground product flows, and the complete literary evaluation remain additional observations; their absence is explicitly waived as a Rust-start prerequisite. Real single-display validation at all four system scaling settings remains mandatory.
