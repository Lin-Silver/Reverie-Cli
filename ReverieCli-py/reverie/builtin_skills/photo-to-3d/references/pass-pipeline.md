# Pass pipeline

Eight passes, in order, each with an entry gate, a deliverable, and an exit gate. The exit gate is checked against a render, not against intent. A failed gate means re-run the pass.

Record every pass in `state.json` (contract in [render-review.md](render-review.md)) as `pending` → `in_progress` → `review` → `locked`.

## 1. Blockout

- **Entry**: reference image read; subject classified; real-world size stated in metres.
- **Do**: one grey primitive per major volume. `BoxGeometry`, `CylinderGeometry`, `SphereGeometry` only. Position and scale, nothing else.
- **Exit**: the silhouette from the front and side cameras reads as the subject; the overall bounding box matches the stated real size within 5%; part-to-part proportions match the reference within 10%.

## 2. Structural

- **Entry**: pass 1 locked.
- **Do**: settle the final `THREE.Group` tree and every node name. Split volumes into the parts that carry load or define assembly: frame, chassis, shell, trunk, walls, floors, limb chain. Attach parts to their parent, not to the root, so a later transform moves the right subtree.
- **Exit**: every part visible in the reference has a named node; no node is parented to the root that should follow another part; renaming after this pass is a re-run, not an edit.

## 3. Form

- **Entry**: pass 2 locked.
- **Do**: replace boxes with the real profile. `LatheGeometry` for anything turned or bottle-like, `ExtrudeGeometry` with `bevelEnabled` for plates and panels, `TubeGeometry` along a `CatmullRomCurve3` for cables, handles, and trim, `ShapeGeometry` for flat cut-outs. Round every edge the reference shows as rounded; a razor edge reads as "untextured CAD" even after materials.
- **Exit**: the silhouette matches the reference at all four review cameras; no remaining placeholder primitive stands in for a shaped part; segment counts are deliberate, not default.

## 4. Material

- **Entry**: pass 3 locked. Character subjects finish the de-lighting step in [character-track.md](character-track.md) first.
- **Do**: assign one material per distinct real material, not per mesh. Sample base colour from the reference and convert out of the photo's lighting. Set `roughness`, `metalness`, `clearcoat`, `transmission`, `ior`, and `sheen` from what the surface physically is. See [materials.md](materials.md).
- **Exit**: no material still has the Three.js defaults; metals read as metal and dielectrics as dielectric under the pass-6 rig; sampled colours are written into `state.json` as hex values so a later pass can audit them.

## 5. Surface

- **Entry**: pass 4 locked.
- **Do**: add detail procedurally. Noise-driven grain, weave, brushed anisotropy, edge wear on convex edges, panel lines, stitching, logos as generated canvas textures. Vary roughness before varying colour — most real surface reads as roughness breakup.
- **Exit**: no large surface is perfectly uniform; every added detail exists in the reference; no bitmap texture was downloaded or generated by an image model.

## 6. Lighting

- **Entry**: pass 5 locked.
- **Do**: build the rig the model ships with. Either a three-point setup (key, fill, rim) with a soft ground bounce, or an environment map plus one directional key. Set `toneMapping`, `toneMappingExposure`, and `outputColorSpace` explicitly. Enable shadows only where they read.
- **Exit**: the model is legible from all four cameras without a per-camera light hack; no blown highlights and no crushed blacks; the rig is committed to code, not left in the harness.

## 7. Interaction

- **Entry**: pass 6 locked, and the user actually asked for behaviour.
- **Do**: expose parameters on the factory, add `AnimationClip`s or an update callback, wire hover/click via raycasting or react-three-fiber props. Keep the factory usable without any of it.
- **Exit**: every interaction has been exercised in the harness with a screenshot or console evidence; the static factory still renders unchanged when interaction is unused.

## 8. Optimization

- **Entry**: pass 6 locked (7 too, when present).
- **Do**: merge static sibling geometry, share materials, reduce segment counts where the render cannot tell, dispose anything created and discarded, and add a `dispose()` on the returned group.
- **Exit**: a before/after render pair shows no visible regression; `renderer.info` draw calls, triangles, and geometry/texture counts are reported against the stated budget.

## Re-running a locked pass

Allowed, but never silently. Set the pass back to `in_progress`, write the reason in its `notes`, set every pass below it back to `pending`, and re-run them. Tell the user which passes were invalidated.
