# AiO 与独立对话

当前对话配置和工作区默认配置分别保存。工作区默认值用于创建新对话；已有对话保持自己的模型、请求参数、模式、规则、技能、插件选择与权限偏好。模型目录及凭据仍由应用统一管理，对话保存稳定引用。模型引用失效时会报出缺失项，保留原选择。

AiO 参考了 DeepSeek 的 [Super-agent 研究原型](https://github.com/deepseek-ai/dsh-superagent-prototype)中[事件与任务身份](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/001-domain.md)、[执行与恢复](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/003-execution.md)及[持久化与有限缓存](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/007-architecture.md)的设计：事件先持久化、同一主线的判断串行、判断期间到达的回复继续处理、任务状态独立于执行代理状态、结果回到原对话、发言使用消息身份去重。实现使用 Reverie 自己的内核、权限、模型接口和执行协调器，没有引入 DeepSeek Harness 或该原型的运行依赖。工作槽位、桌面执行边界和主动陪伴行为遵循本项目的验收方案。

桌面端切换工作区和对话不会停止后台任务。结果、审批、草稿、附件及待发送消息属于原对话。普通对话继续在创建时的工作区执行；AiO 主线拥有独立的应用身份，任务分支记录各自的工作区。

## 使用

- 设置中的“配置范围”选择“当前对话配置”或“工作区默认配置（用于新对话）”。任务入队时固定配置，此后的配置变更只影响新任务。
- 在桌面端选择 AiO 模式，或在设置的 AiO 面板启用助手。首次启用继承当前模型，此后在 AiO 主线中单独选模型。
- “主动发言与电脑观察”开启后，助手最多每分钟主动判断一次。关闭后停止常规观察、判断和弹窗，已开始的任务继续保存结果。用户回复和任务结果走独立的持久队列。
- AiO 发言窗支持完整文本、滚动、复制、直接回复和打开原对话。显示时不抢焦点；任务消息的回复回到任务分支，日常消息的回复回到主线。
- AiO 面板与托盘提供暂停／恢复。关闭主窗口收进托盘；明确退出应用会结束所属内核和终端进程。首版不设置登录自启动。
- 长期记忆可以查看、纠正和删除。推断保留其来源与可信程度；被删除或纠正的旧证据不会再次自动生成同一记忆。
- AiO 主线不提供删除，只支持归档与分段。主线分叉会在当前工作区创建独立分支，复制完整原文和当时配置，保留原主线；任务分支可以删除。
- 终端共享对话配置与持久化，SDK 提供 AiO 接口；主动观察、调度、发言窗和跨对话后台协调由桌面宿主运行。旧 Computer 入口迁移为 AiO，历史保留旧模式来源。

## 保存与迁移

每个工作区的数据目录使用 `conversations.sqlite3` 作为消息、配置版本、任务关联、导航状态及已提交流片段的权威来源。AiO 独立使用应用数据根的 `.reverie/aio/`，含长期主线、日期／上下文分段、任务分支、决策、观察证据、待处理事件、发言队列与助手记忆。

SQLite 使用 WAL、完整持久化、短事务和递增版本号。流片段按 250 毫秒或 16 KiB 边界提交。完成消息及任务终态只有提交成功后才确认；提交失败对用户可见，重启会恢复已经提交的部分，并标记中断。界面首屏分页读取，不需要加载全部历史。主动发言先保存再展示，未确认送达的窗口在重启后标记为不确定，避免盲目重复显示。

模型回答保存时保留原始首尾空格和换行，截断后续写的片段也保留原文；界面展示仍沿用既有正文清理。显式协议结束标记继续按原有规则处理。

已展开的历史分页在任务完成、配置刷新及返回缓存对话时继续保留。刷新只补入新消息；较长任务的新消息跨越多页时，按页补齐中间记录。回退造成历史缩短时使用回退后的记录，分页版本不一致时显示错误，避免把不同版本拼在一起。

自动上下文压缩在同一对话新增摘要分段，已确认原文继续保留在 SQLite 消息分页中。摘要和近期原文用于后续模型上下文，近期重放不重复保存为新消息。匿名 OpenAI Chat 网关的压缩与接续沿用普通请求的 HTTP 路由及配置端点。

工作区全局记忆通过当前请求的临时上下文提供，不在每次刷新时插入或替换已保存消息。旧历史中已经保存的记忆系统消息继续保留用于查看及导出；新模型请求采用当前检索结果，避免重放旧摘要，也不会使原消息身份和序号移动。

旧 JSON 对话按批迁移，迁移记录支持重跑及中断续迁。旧文件保留，不自动删除。没有历史模型证据时，使用迁移时工作区默认配置并记录来源。数据库升级前通过 SQLite 在线备份保存一致快照；已完成迁移的数据库读取失败不会静默恢复到旧 JSON。JSON／Markdown 导出继续可用，存储接口保存角色转换规则及配置版本。

截断 JSON、非对象 JSON 或无法按 UTF-8 解码的旧文件会记录原路径并跳过，正常列表及其他迁移继续；显式加载该损坏会话返回清晰错误，原文件保持不变。代理认证保存在共享配置中，快照和配置导出只保存去除认证的地址；运行时仅在地址相同时解析当前共享认证，避免旧凭据重放或转发到其他端点。

AiO 主线始终是 `aio-mainline`。分段摘要是上下文入口，原文继续保留。助手上下文组合近期主线、相关阶段摘要、相关记忆与任务状态；项目任务只接收相关助手偏好及当前工作区记忆。观察证据与用户消息分开保存。

归档状态保存在对话的事务元数据中，旧桌面设置里的归档列表只用于一次迁移。AiO 主线归档随助手身份保存，切换工作区后仍有效。`archiveSession` 请求携带对话归属和版本，`listSessions` 返回权威归档状态。工作区统计使用独立的 `workspace_stats.sqlite3`，从旧统计 JSON 导入一次并保留原文件；多个内核提交各自的增量，避免旧统计副本覆盖其他任务的用量。

AiO 的 JSON／Markdown 导出附带阶段摘要、任务分支、任务配置及验收记录，并在同一目录生成 `.aio-events.jsonl` 文件保留相应原始事件及发言送达状态。主线导出涵盖助手事件，分支导出只包含本分支事件。分享或搬运导出时应同时保留正文、事件文件和所引用的附件。

## 并行文件任务

桌面端普通任务与 AiO 共用最多四个执行槽位。同一对话保持单个执行回合；多项并行工作使用任务分支。Git 写任务在隔离目录执行，基础快照包含启动时的已跟踪修改和未忽略文件，并保留字节内容与原暂存状态。普通任务成功完成后汇入相对基础快照的改动；带验收条件的任务须通过额外验证后汇入。重叠冲突会保留隔离结果，并显示具体文件；不会覆盖用户修改。非 Git 工作区写任务串行，只读任务可并行。

选择关联 Git checkout 或其子目录时，任务基础快照、执行路径和汇入目标均属于所选 checkout；仓库的主要 checkout 只用于托管隔离目录的生命周期登记。

带验收条件的任务分别记录“代理结束”和“验证完成”。重启后的中断任务先核对实际效果；桌面动作结果不确定时不得直接重放。工作子代理不控制桌面，桌面执行由 AiO 主代理与现有桌面占用协调管理。

## 接口归属

所有对话操作显式携带 `projectRoot`、`sessionId`，AiO 额外携带 `assistantId: "aio"`。后台加载和保存不改变“上次查看的对话”。任务执行目录通过 `executionRoot` 区别于对话归属工作区。

接口包括 `getConversationConfig`、`getWorkspaceConfig`、分页 `getSession`、`queueConversationRun`、`updateConversationRun`、`listConversationRuns` 与 `recoverConversationRuns`。配置及任务状态更新携带对应版本。AiO 使用 `aioState`、`aioControl`、`aioDecision`、`aioPendingTasks`、`aioTaskState`、`aioMessages`、`aioMessageState`、`aioReply`、`aioPendingSignals`、`aioAcknowledgeSignal` 及 `aioMemory`。
