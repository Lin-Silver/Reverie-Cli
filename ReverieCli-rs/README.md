# Reverie CLI 3.0.0 Rust workspace

This workspace implements the native first-party kernel and terminal migration. Development is on `main`; the final Python 2.5.5 project is frozen on `Reverie-Cli-py`. The full product scope is in [the migration plan](../tasks/rust-3.0/plan.md); [unverified items](../tasks/rust-3.0/UNVERIFIED.md) and [the cloud validation prompt](../tasks/rust-3.0/CLOUD_VALIDATION_PROMPT.md) track remaining evidence.

Rust/Cargo 1.96.0 and Edition 2024 are fixed. Build with `cargo build --manifest-path ReverieCli-rs/Cargo.toml --release --locked` from the repository root. The output is `ReverieCli-rs/target/release/reverie` (`reverie.exe` on Windows).

The native program provides version/help, `--kernel-info`, and UTF-8 JSONL `--sdk-bridge`. Configuration and session actions support bootstrap/state, existing manual-model profiles, settings, independent conversation snapshots, durable SQLite transcripts, paging, naming, archiving and confirmed deletion. The bridge preserves string/number request IDs, reports malformed input, and closes on `shutdown` or EOF. Capabilities declare implemented actions; unsupported actions return explicit errors. Conversation schema 7 and the stored `Reverie`/wire `assistant` role convention remain compatible. Existing databases are backed up through SQLite before Rust writes, and configuration edits preserve unknown fields with an original-byte backup.

The in-process Context Engine supports persistent incremental indexing and native Python, JavaScript, TypeScript/TSX, Rust, C/C++, C#, Go, Java, Zig, HTML/CSS, Lua and GDScript parsing. It retains symbol metadata, documentation, parent scopes, directional references, text/document/game-resource fragments, lexical and literal CJK queries, paths, source SHA-256 validation and bounded evidence. Use SDK `indexWorkspace`, `queryContext`, `getContextStatus`, the native `codebase-retrieval` model tool, or `reverie --context-engine --help` for standalone commands. `lookup <database> <request-json>` supports symbol, file, search, dependencies, outline, explore and task requests. Static resolution explicitly distinguishes inference, ambiguity and unresolved targets. Development schema 2 indexes are consistently backed up before schema 3 migration; parser revision changes trigger a transactional rebuild without discarding the prior revision on failure. Its database is separate from legacy Python indexes. Complete language constructs and reference resolution, local semantic models, hybrid fusion and neural reranking remain in progress.

Local semantic CLI commands validate explicit offline resources, run E5 embedding/BGE reranking, build persistent normalized vectors and retrieve hybrid evidence with reciprocal-rank fusion. Use `semantic-probe`, `semantic-index` and `semantic-search` from `--context-engine --help`. CPU is the baseline, requested GPU failure reports its reason and falls back to CPU, and models can unload. The shared SDK and Agent now use this chain; Electron provides a Context Engine page and the terminal provides `/context` management. Resource candidates load actual models and pass a second integrity check before atomic activation; active tasks retain their selected version, cancelled indexing preserves the previous generation, and mapped runtimes remain until restart. Exact cosine retrieval currently uses a bounded heap; this is not ANN. Actual Windows FP32, generic INT8 and resource lifecycle checks passed. Automatic semantic catch-up, full quality/latency, recovery and four-platform inference remain in progress; [phase2.md](../tasks/rust-3.0/phase2.md) records their status and resource provenance.

The execution path supports OpenAI Chat/Responses, Anthropic Messages and Gemini HTTP/JSON/streaming protocols, actual workspace file and command tools, explicit approvals and structured user questions. `runPrompt` streams events until its final `prompt.result`; `stopPrompt` cancels the identified run. Streamed partial output survives cancellation or truncated responses. Running conversations keep their own project and configuration while other conversations execute. `resolveApproval` accepts once/session/deny/message, and `resolveUserInput` submits a question's explicit answer. Electron now connects to the same resident Rust kernel. Complete provider/account capabilities and Auto Check review continue in subsequent increments.

Running `reverie` in an interactive terminal opens a scrolling conversation using the same Rust kernel library as the SDK. It retains terminal scrollback, grapheme editing, multiline input, streaming replies, model/conversation menus, three-option questions with a custom answer, and explicit approvals. Use `/help` for the implemented commands. Enter submits; Ctrl+J inserts a newline, and terminals that report modifiers also support Shift+Enter/Alt+Enter. Bracketed paste stays in the editor until explicit Enter. Windows reads VT-preserving console records directly and closes without a blocking input thread. Copy, physical keyboard/IME behavior and the complete terminal matrix still require broader acceptance. Splitting a paste boundary across separate ConPTY host writes currently loses that boundary before it reaches Rust; this remains a documented unresolved host case.

Use `reverie --prompt "text" --project <directory> --no-index --json` for a single native run, or pipe text with `--project`. This entry returns an error/cancelled result if an explicit question or approval is needed; it does not invent a response.

Run `node scripts/verification/rust-smoke.mjs`, `node scripts/verification/rust-session-smoke.mjs`, `node scripts/verification/rust-context-smoke.mjs`, `node scripts/verification/rust-run-smoke.mjs` and `node scripts/verification/rust-tui-smoke.mjs` against the built release program for basic actual-process checks. Install the desktop development dependencies with `npm ci --prefix ReverieCli-ui --ignore-scripts` for the PTY and headless terminal emulator. The model fixture is a loopback HTTP server; all file operations are executed by the native program. These checks do not establish complete product, legacy data, performance, external model, DPI, game, or release acceptance.

All first-party crates use the repository's MIT license. Serde 1.0.229 and serde_json 1.0.154 were verified against Crates.io metadata as available and not yanked, under MIT OR Apache-2.0. Ratatui 0.30.2, Crossterm 0.29.0 and Windows-only Termwiz 0.23.3 declare MIT; unicode-segmentation 1.13.3 and unicode-width 0.2.3 declare MIT OR Apache-2.0. The Termwiz crate was checked against its registry SHA-256 before consulting its input parser. The headless xterm 6.0.0 dependency is for validation only and declares MIT. Cargo.lock pins the complete dependency graph; final binary notices and dependency license auditing remain part of the release work.
