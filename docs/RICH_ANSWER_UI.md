## 使用方式

正常描述要展示的内容即可，例如：

- “把这些项目整理成统计卡片和项目总览表，状态用标签显示。”
- “推荐这些软件，展示图片、适用理由、来源和官网链接。”
- “只用普通文字回答。”

Desktop 模型提示词已说明可用格式。普通段落、标题、列表、代码、Markdown 表格仍可使用；需要改变输入、筛选、排序或填写表单时，仍由已有交互视图提供真实控件。

卡片和表格使用宿主主题，不依赖模型自行编写配色与布局。窄容器中保持内容可读，较宽的表格可单独横向滚动；外部链接由系统浏览器打开。图片支持 HTTPS 和内嵌的 PNG、JPEG、WebP、GIF、AVIF 数据；无法加载时保留图片说明。来源标签表示回答提供了链接，不代表宿主已经核实了该来源。

普通指标继续使用参考图中的四卡片布局。长数字指标改为最多两列，数字保持单行且可键盘聚焦、横向滚动；窄表格也在独立可聚焦区域内横向滚动。指标、表格和推荐卡片文字保留输入中的空格与换行。带图推荐卡在宽屏采用图文并排，窄屏维持可读的图文布局；图片有替代文本与加载失败回退。最终桌面深浅主题、宽窄屏截图和原生检查见[2026-10-26 富格式 UI 证据](verification/2026-10-26-rich-answer-ui/README.md)。

## 供开发者与模型作者使用的格式

用语言标识为 `reverie-ui` 的代码围栏承载一个 JSON 对象，Desktop 会把完整、合法且没有重复键或未支持字段的对象显示为对应 UI。数字按原始 JSON 字面值显示，避免大整数或高精度小数在界面转换时被改写。格式无效时保留完整原始内容；流式输出未完成时显示整理提示。会话保存原文，重开后使用同一渲染器恢复，无需保存另外一份 HTML。

用户要求在聊天中展示、总结或比较静态信息时，统计卡片、表格和推荐卡应直接作为回答输出；不要为静态布局创建文件或调用交互视图工具。只有用户要求保存/导出文件，或任务需要可操作控件时，才分别创建文件或交互视图。

### 统计卡片

```json
{"type":"metrics","items":[{"label":"计划中","value":7},{"label":"开发中","value":5},{"label":"已有成果","value":4},{"label":"半归档","value":1}]}
```

以上数字仅用于说明格式。宿主不会填充或推断项目数据。

### 总览表与状态标签

```json
{"type":"table","title":"项目总览表","columns":["项目名称","当前状态","说明"],"rows":[["示例项目",{"text":"开发中","tone":"info"},"项目说明"]],"caption":"统计范围说明"}
```

每行与表头列数一致。单元格可为字符串、数字、布尔值、null，或包含 `text` 与可选 `tone` 的标签。标签支持 `neutral`、`info`、`success`、`warning`、`danger`；文字明确说明状态，颜色仅作辅助。零、false 和空值不会被其他默认值替换。

### 图文卡片

```json
{"type":"cards","numbered":true,"items":[{"title":"软件名称","description":"适用理由","badge":{"text":"推荐理由","tone":"success"},"image":{"url":"https://example.org/observed-screenshot.png","alt":"图片说明"},"details":["许可或价格说明"],"sources":[{"label":"来源名称","url":"https://example.org"}],"links":[{"label":"官方网站","url":"https://example.org"}]}]}
```

每项只要求 `title` 与 `description`；其余字段可省略。使用用户提供或已经观察到的真实图片地址与来源，缺失时省略。示例域名不是真实来源，不应复制到实际回答中。

### 独立来源

```json
{"type":"sources","items":[{"label":"来源名称","url":"https://example.org"}]}
```

## 边界

这些格式只表达数据，不接受 HTML、脚本、任意样式或宿主操作。图片不能通过此格式读取本地文件；链接不接受脚本、文件协议或内嵌凭据。HTTPS 图片只能用于图片元素，未放开脚本、连接或交互 iframe 的权限。
