# Context Engine implementation sources

The initial `catalog.rs`, `parsing.rs`, `scan.rs`, `search.rs`, `text.rs` and SQL schema were recovered from this repository's MIT-licensed Rust indexer at commit [`f029496d19138176b857bedb54f7eeb225973471`](https://github.com/Lin-Silver/Reverie-Cli/tree/f029496d19138176b857bedb54f7eeb225973471/ReverieCli-py/native/context-engine). The original source remains in Git history and the historical mixed Python release. The final Python 2.5.5 archive does not depend on this implementation.

The 3.0 implementation uses an in-process library, Git directory exclusion, a separate versioned database with source identities and persisted evidence text, bounded evidence fragments and a shared query API. These changes are Reverie CLI changes under the repository MIT license. No legacy worker or Python adapter is included. Parser, SQLite and ignore dependencies remain separately licensed; Cargo.lock records their exact versions.

The symbol, file, search, dependency, outline, exploration and task request fields follow the actual Python tool and index contracts in the fixed final Python source [`070fa25b07692c90c56a6b00a9a969ff2abb7804`](https://github.com/Lin-Silver/Reverie-Cli/tree/070fa25b07692c90c56a6b00a9a969ff2abb7804/ReverieCli-py/reverie/context_engine) and its `tools/codebase_retrieval.py`. The new Rust graph and lookup are independent implementations under the same repository license. Grammar tag queries come from the pinned Tree-sitter crates; inference is explicitly labelled and is not an LSP or compiler resolution claim. `tests/fixtures/rust-schema-v2.sql` preserves the development schema from `9ca0212` for actual backup, migration and restoration checks.

The additional grammars below were checked against Crates.io metadata, their packaged source commit and actual license text on 2026-11-23. Each declares MIT. Copies of their applicable copyright and permission texts are retained in [licenses](licenses); final packages must include these texts with the other binary dependency notices. The six licenses not found at their crate roots were retrieved from the fixed upstream revisions, including Lua's `LICENSE.md`.

## Local semantic inference and resources

`inference.rs`, `semantic.rs` and `semantic_context.rs` are independent Reverie implementations. FastEmbed 7.7.1 is fixed under Apache-2.0; its actual packaged license is retained as [fastembed-LICENSE](licenses/fastembed-LICENSE). The registry package records source revision `98de7ca95d35e5407c3859da8a75db133bb5fd35` with `dirty=true`; this identifies its declared origin, not a claim that the package equals a pristine Git checkout. `ort` and `ort-sys` 2.0.0-rc.15 declare MIT OR Apache-2.0 and source revision `5c564c58507f35fa4adc387a79fce1016e73956b`. Their applicable texts are retained as [ort-LICENSE-MIT](licenses/ort-LICENSE-MIT) and [ort-LICENSE-APACHE](licenses/ort-LICENSE-APACHE). Cargo.lock, rather than an unverified source checkout, fixes the downloaded crate bytes. Inference uses explicit local resources and dynamic ORT loading; hub clients and implicit runtime downloads are disabled.

The resource producer fixes `intfloat/multilingual-e5-small` to `614241f622f53c4eeff9890bdc4f31cfecc418b3` and `BAAI/bge-reranker-base` to `2cfc18c9415c912f9d8155881c133215df768a70`. Their actual model cards declare MIT and are copied with the resource assets. Original LFS identities, tokenizer Git blobs, the official ORT NuGet SHA-256 and all produced asset hashes are recorded in the bundle manifest. ORT 1.31.0's actual native library and packaged license/third-party notices are separate from the Rust wrapper license. Full model/tokenizer and binary dependency notices must still be checked for redistribution; reading model license metadata is not the entire release license audit.

`scripts/resources/quantize-semantic-models.py` is an external resource-production tool using fixed ONNX 1.23.2 and ONNX Runtime 1.31.0 packages. Dynamic QInt8 quantizes constant MatMul/Gemm and Gather weights, with per-channel and reduced range enabled. The manifest records the producer script, Python version, wheel hashes and parameters. The Rust client does not execute Python. The FP32 control and initial MatMul-only candidate remain separate; native basic loading and retrieval of the Gather candidate do not establish full quantization quality or warmed latency.

Semantic storage uses complete transactional generations, preserves the latest generation for each resource digest plus the immediately previous generation, and reads vectors/evidence in one SQLite snapshot. Exact cosine retrieval currently uses a bounded heap, followed by reciprocal-rank fusion and local neural reranking. This is not an ANN/HNSW implementation. Resource activation, task model leases, full concurrency and resource removal are subsequent integration work; native cancellation is checked between inference calls rather than interrupting an in-flight ORT call.
